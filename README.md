# Flight Crew Demand Analysis

UBIKAIS 운항자료에서 공항별·운영일별·시간대별 동시 조업조 수요를 계산하는 Streamlit 앱입니다.
출발·도착 1편당 각각 1개 조를 점유하며, 결과 단위는 **개 조**입니다.

소스 저장소: [ohsunbi/flight_demand_analysis](https://github.com/ohsunbi/flight_demand_analysis)

## 현재 상태

계산 엔진, URL 설정 복원, 클릭 히트맵·오른쪽 상세, PNG·A4 PDF 출력을 구현했습니다.
인천·김포·제주 표본 수집, 인천 하루의 예정/실제 우선 계산과 보고서 출력을 확인했습니다. Cloud 배포는 아직 수행하지 않았습니다.
시간대는 사용자의 기존 운영 확인에 따라 한국시간으로 처리합니다.
**실제 날짜가 없는 HHMM은 사용자 합의에 따라 예정시각에 가장 가까운 날짜로 계산합니다. 날짜 추정 편수를 표시하며, 하루 이상 지연된 편은 날짜가 부정확할 수 있습니다.**
가상 테스트 통과와 실제 표본 검증, 아직 검증하지 않은 범위를 구분합니다. 상세 현황은 `project_context.md`와 `docs/data_contract.md`를 참고하세요.

## Windows 설치와 실행

Python 3.12와 [uv](https://docs.astral.sh/uv/getting-started/installation/)를 사용합니다.
프로젝트 루트에서 실행하세요.

```powershell
uv sync --locked
uv run --no-sync streamlit run app.py
```

참조 프로젝트 폴더는 필요하지 않습니다. 최초 접속은 설정만 표시하며 자동 API 조회하지 않습니다.

## 사용 방법

1. 공항과 월별/사용자 지정 기간을 선택합니다. 양 끝 날짜를 포함해 최대 31개 운영일입니다.
2. 공항을 선택하면 **JJA와 공항별 조업 항공사의 ICAO 영문 3자리 코드**가 자동 입력됩니다. 필요하면 직접 추가·삭제하고 여러 항공사는 쉼표로 구분합니다. 같은 공항에서 다른 조건을 바꿀 때는 수동 입력을 유지하며, 공항을 바꾸면 새 공항의 기본 목록으로 교체합니다. 최소 1개가 필요하며 전체 항공사 분석 선택은 제공하지 않습니다. 원본은 날짜·출발/도착별 전체 자료를 수집한 뒤 입력한 ICAO 접두어로 선별하고, 편명을 판별하기 어려우면 해당 날짜·방향을 항공사별로 다시 조회합니다. 표시용 목록에 없는 코드도 형식이 맞으면 선택할 수 있습니다. 상세 편명과 결과·보고서 항공사는 IATA 2자리로 표시하며, 대응표에 없으면 원래 코드를 유지합니다. 입력란의 `?`에 마우스를 올리면 쉼표 입력 안내와 입력된 코드의 IATA 표시를 확인할 수 있습니다.
3. 분석 기준시각을 **계획 (STA/STD)** 또는 **실제 (RAMP IN/OUT)** 중 선택합니다. 실제시각이 없으면 STA/STD를 사용합니다.
4. 출발편·도착편 시간설정의 **사용**으로 대상 방향을 선택합니다. 기본은 둘 다이며 최소 하나가 필요합니다. 해제한 방향의 시간 입력값은 보존하고 조회·계산에서는 제외합니다. 제외 방향의 시작/종료 순서나 재투입 범위 오류는 선택 방향의 분석을 막지 않으며 다시 선택하면 검사합니다. 결과·보고서의 제외 방향은 `—`로 표시합니다. 필요하면 시간대 구분 간격, 조업 개시 시간과 조업시간을 변경한 뒤 **분석 실행**을 누릅니다. 조업 개시 시간은 한국시간 기준 하루 집계의 경계이며, 30분 단위로 선택합니다. 기존 URL의 분 단위 값은 그대로 복원합니다.
5. 히트맵 셀을 클릭하면 오른쪽에 피크·점유 겹침·기준시각 운항편 목록이 표시됩니다.
6. 수집·품질 검사를 통과한 결과에서 히트맵 오른쪽 위 **다운로드** 메뉴의 **PNG / PDF**를 선택합니다. 클릭할 때 선택한 파일만 생성하며 같은 결과는 재사용합니다. 두 형식은 제목·공항·항공사·기간·오전/오후 최대 수요·출발/도착 편수·분석 조건과 히트맵을 같은 양식으로 출력합니다. 발생일·범례·하단 안내는 제외합니다. A4 세로로 최대 31일 전체를 표시하며 60분 분석은 단일 PNG/PDF 1장, 30분 분석은 12시간씩 나눠 PNG 2개를 ZIP으로, PDF는 2장으로 제공합니다.

실제 우선은 출발 주기장 출발·도착 주기장 도착시각을 사용하고 없으면 STD/STA를 사용합니다.
이륙·착륙·예상시각을 중간 대체값으로 사용하지 않습니다. 편수도 선택한 기준시각으로 집계합니다.
날짜 추정은 예정일 전날·당일·다음날 중 예정시각에 가장 가까운 시각을 선택합니다. 정확히 12시간 동률이면 예정일 당일을 선택합니다.
확인된 결항 CNL은 제외합니다. 특정 항공사는 API의 조회 코드 기준이며 검증된 실제 운항사 필드로 가장하지 않습니다.

기본값: 인천 항공사 JJA·TTW·AXM, 조업 개시 시간 00:00, 분석 간격 60분(30분 선택 가능), 출발편 조업 시작 -50분/종료 +10분/이동 10분, 도착편 조업 시작 -20분/종료 +30분/이동 10분.

공항별 기본 항공사는 인천 JJA/TTW/AXM, 김포 JJA/TTW, 제주 JJA/CQH/HKE, 김해 JJA/HKE/CQH/CDC, 청주 JJA/CSC/RLH/CDC, 대구 JJA/HKE/ESR/CSC/QDA/CDC/LKE/CBJ이며 나머지 공항은 JJA입니다. 사용자 지정 조업 목록으로, 공항의 전체 취항 항공사 목록이나 자동 갱신 자료가 아닙니다.
조업 시작·종료는 선택한 기준시각 대비 값이고 이동소요 시간은 종료 후 걸리는 시간(0분 이상)입니다. 재투입 가능 시각은 조업 종료 + 이동소요 시간으로 계산하며, 이동 중에도 조를 점유합니다. 조업 시작이 종료보다 늦거나 계산한 재투입 가능 시각이 기준시각 대비 ±7일을 벗어나면 경고하고 조회를 차단합니다.
기존 URL의 재투입 가능 값은 이동소요 시간 = 재투입 가능 − 조업 종료로 복원하므로 같은 설정의 수요 결과를 유지합니다.

편수는 해당 시간대의 기준시각을 가진 운항편 수입니다. 필요 조업조 수는 그 시간대의 **최대 동시 점유 수**이므로 서로 다릅니다.
인접 날짜 편이 점유에 기여할 수 있어 수집에는 31일 외의 보충 날짜가 필요할 수 있습니다.

## 설정 URL

PNG와 PDF는 같은 양식과 A4 세로 용지 비율을 사용합니다. 60분은 1장, 30분은 12시간씩 나눈 2장으로 구성합니다.

URL 버전은 3이며 항공사는 ICAO 3자리로 저장합니다. 버전 없는 URL도 현재 ICAO 입력으로 처리합니다. 항공사가 명시된 URL은 빈 값까지 그대로 복원하고, 생략되면 해당 공항의 기본 목록을 사용합니다. 기존 버전 1·2 및 잘못된 URL은 기본 설정과 안내를 표시합니다. 구버전 URL 변환은 지원하지 않으며 URL 복원만으로 자동 조회하지 않습니다.

분석 방향은 `directions=dep`(출발), `arr`(도착), `dep,arr`(양쪽)로 저장하며 생략 시 양쪽을 선택합니다. 선택하지 않은 방향의 시간 입력도 보존합니다.

유효한 설정 변경은 주소창 URL에 반영됩니다. URL을 복사해 다시 열면 조건을 복원합니다.
자동 수집하지 않으며 조회 버튼을 눌러야 합니다. 같은 URL도 자료 변경에 따라 결과가 달라질 수 있습니다.
입력 조건과 적용 결과는 구분하며 조회 실패 시 이전 결과를 유지합니다.
자료·사용자 설정의 영구 DB는 없습니다. 서버 캐시는 일시적인 성능 최적화입니다.

표시용 항공사 변환표는 `config/airline_codes.py`에 포함합니다. 읽기 전용 참조 프로젝트에서 2026-10-29 확인한 309개 대응표·출처·편명 변환 함수를 독립 복사하고, 사용자 승인 `XUM → XU`와 IATA 공식 자료로 확인한 `LKE → 8L`을 추가해 311개를 사용합니다. `ASA`는 `AS`로 표시합니다. 전 세계 항공사의 완전한 목록은 아니며 실행 중 외부 코드 목록을 조회하지 않습니다. 원본 편명·조회 코드·계산 데이터는 표시 변환으로 바꾸지 않습니다. 구버전 URL 복원 자료였던 `config/airlines.json`은 제거했습니다.

전체 수집과 편명 판별 실패 시의 개별 조회를 합쳐 분석 한 번당 최대 1,000개 조회 단위를 허용합니다. 조회 단위는 날짜·방향·조회 조건의 조합으로, 페이지 수집·재시도 때문에 HTTP 요청 수와는 다릅니다. 요청은 한 번에 하나씩 최소 0.35초 간격으로 처리하며 기존 원본 캐시·새로 조회·중단 기능을 유지합니다. 수집 실패는 0편으로 처리하거나 다른 조회로 숨기지 않습니다.

## 인증정보

필요한 경우에만 `UBIKAIS_COOKIE` 환경변수 또는 `.streamlit/secrets.toml`의 같은 키로 주입합니다.
실제 값을 코드·URL·Git에 넣지 마세요. 비밀값 없는 설정 예시는 다음과 같습니다.

```toml
UBIKAIS_COOKIE = "여기에_본인_세션값을_로컬에서만_입력"
```

## 개발 검증

```powershell
uv sync --locked --group dev
.venv\Scripts\python.exe -m pytest -q
.venv\Scripts\python.exe -m playwright install chromium
```

브라우저·보고서 기능을 가상 데이터로 확인하려면:

```powershell
$env:CREW_DEMO = '1'
uv run --no-sync streamlit run app.py
```

화면과 보고서에 가상 데이터 표시가 붙습니다. 이 환경변수를 실제 운영에 설정하지 마세요.
가상 모드를 해제하려면 서버를 종료한 뒤 다음과 같이 실행합니다.

```powershell
Remove-Item Env:CREW_DEMO -ErrorAction SilentlyContinue
uv run --no-sync streamlit run app.py
```

상세 검증 명령은 `docs/verification.md`를 참고하세요.

## Streamlit Community Cloud

실제 Cloud 배포는 아직 수행하지 않았습니다. 표본 범위 밖 검증과 운영 설정을 확인한 뒤 다음과 같이 배포합니다.

1. GitHub 저장소 `ohsunbi/flight_demand_analysis`의 `main` 브랜치를 사용합니다. 캐시·비밀값·가상 검증 산출물은 제외되어 있습니다.
2. Community Cloud에서 저장소·브랜치를 지정하고 실행 파일을 `app.py`로 선택합니다.
3. Advanced settings에서 Python **3.12**를 선택합니다.
4. 필요한 경우 Secrets에 인증정보를 설정합니다. `CREW_DEMO`는 설정하지 않습니다.
5. 공개 접근 설정과 신규 세션, 단일/복수 항공사, 코드 미입력 시 조회 차단, 다운로드를 실제 Cloud에서 확인합니다.

`pyproject.toml`과 `uv.lock`이 의존성 기준이고 `requirements.txt`는 동일 lock에서 생성한 보조 파일입니다.
개발용 브라우저/PDF 검사 패키지는 기본 설치 그룹에서 제외했습니다.

공식 안내: [배포](https://docs.streamlit.io/deploy/streamlit-community-cloud/deploy-your-app/deploy),
[Python 선택](https://docs.streamlit.io/deploy/streamlit-community-cloud/manage-your-app/upgrade-python).

개발을 이어갈 때는 `project_context.md`부터 확인하세요.
