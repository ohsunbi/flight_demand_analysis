확인일 2026-10-27. 표본 관측, 사용자 결정, 미검증 범위를 구분한다.

## 확인한 형식·처리

1. 항공사 빈 조건에서 RKSI 26일 출발 627, 도착 634행이 total과 함께 반환됐다. ESR 조건은 각각 25행이었다.
2. `srchAl`은 공식 화면 Flight Number의 앞부분 입력이다. 현재는 빈 조건으로 전체를 수집한 뒤 원본 fpId의 ICAO 접두어로 선별하고, 비표준·누락 편명이 있으면 해당 날짜·방향의 선택 항공사를 이 API 조건으로 개별 조회한다.
   조회 코드를 검증된 실제 운항사로 가장하지 않는다. 공동운항 연결이 없는 유사편을 합치지 않는다.
3. 공식 grid는 `flightPk`를 행 식별자로 사용한다. 공항·방향·원본 예정일을 추가한 내부 키를 사용한다.
4. 출발 STD는 schDate+schTime, 도착 STA는 staDate+sta다. 표본 형식은 YYYYMMDD/HHMM이다.
5. 공식 RAM 열은 출발 blockOffTime, 도착 blockOnTime이다. 표본은 날짜 없는 HHMM이다.
6. 공식 코드가 CNL을 별도 표시하며 실제 표본에도 관측된다. CNL은 결항으로 제외한다.
   DEP/ARR/DLA 외 다른 미확인 상태는 결항으로 추정하지 않고 포함·진단한다.
7. amsRecPkCha는 변경 FPL 팝업 식별자다. 이것만으로 최신 스케줄 순서를 정하지 않는다.
   완전 중복은 합치고 같은 식별자의 상충 내용은 격리한다.
8. limit=5/downloadYn=1 요청에 전체 행이 반환됐다. 클라이언트는 페이지 순회도 지원하고 total·중복 페이지를 검사한다.
9. 공통 코드의 공항 선택 목록에 신규 앱의 16개 공항 코드가 포함된다. 실제 API 표본 조회는 RKSI/RKSS/RKPC만 수행했다.

## 사용자 결정: 시간대와 실제 날짜

- 사용자가 기존 앱과 원본 화면을 한국시간으로 사용했다고 확인했다. 선택한 한국 공항의 시각을 KST로 처리하고 9시간 보정하지 않는다.
- 주기장 실제 날짜가 명시되어 있으면 그 값을 사용한다.
- HHMM만 있으면 예정일 전날/당일/다음날 후보 중 예정시각의 3시간 전 이상인 가장 이른 datetime을 선택한다. 조기 3시간은 포함하며 결과 지연은 21시간 미만이다. 이는 2026-10-30 사용자 승인 정책이며 기존 최근접 날짜 정책을 대체한다.
- 예: 예정 26일 00:05, RAM 23:51 → 25일 23:51.
- 예정 26일 10:00/RAMP 07:00은 26일 07:00, 06:59는 27일 06:59로 추정한다. 1시간과 25시간 지연은 시각만으로 구별되지 않아 1시간으로 추정한다. DLA는 부여 기준이 확인되지 않아 날짜 결정에 사용하지 않는다.
- 이는 **사용자가 채택한 계산 가정**이다. 원본에 실제 날짜가 있다고 표시하지 않는다.
- 화면·상세·보고서에 실제 날짜 추정 편수를 표시한다. 하루 이상 지연은 원래 실제 날짜를 복원하지 못할 수 있다.
- 주기장 시각 결측/형식 오류면 예정으로 대체한다. 둘 다 없으면 격리하고 출력을 차단한다.

## 조회 날짜 범위: 관측에 기반한 운영 규칙

RKSI 3일, RKSS/RKPC 하루 표본에서 예정일-조회일은 0~1일이었다.
RKSI 도착 26일 응답 중 2편의 staDate는 27일이었다. 따라서 조회일=예정일로 단정하지 않는다.

점유·편수에 필요한 예정시각 범위를 산출한 뒤 이전 조회일을 한 번 더 포함한다.
실제 우선은 가까운 날짜 추정의 이동 범위를 포함하도록 앞뒤 1일을 추가한다.
오프셋이 하루를 넘으면 그 크기에 따라 수집 범위도 늘린다.
응답의 예정일-조회일 차이가 0~1일 범위를 벗어나면 계약 변화로 판단해 조회를 실패 처리한다.

퀵턴 활성화 시 연결 작업의 시작·재투입 범위와 제한시간을 함께 반영해 방향별 조회 범위를 넓힌다. 먼저 연결한 뒤 분석 기간에 잘라 집계하므로 전날 도착/당일 출발의 대기 점유도 유지한다. 기존 전체 원본 캐시를 순서 판단에 재사용하며 이를 위한 별도 HTTP 요청을 추가하지 않는다(필요한 보충 날짜 자체는 늘 수 있다).

## 2026-10-30 선택적 퀵턴 모델

- REG=acId, 출발 SPOT=standDep, 도착 SPOT=standArr을 정규화해 보존한다. 공백·대소문자를 정리하고 빈 값·NULL·N/A 등은 미확정으로 취급한다.
- 실제 기준·양방향 선택에서만 적용하며 기본 미적용, 제한시간 기본 100분·1~360분이다. 양쪽 모두 유효한 RAMP가 있고 같은 공항·REG·SPOT인 명확한 연속 도착→출발만 일대일 연결한다. 정확히 제한시간인 간격은 포함하고 0분은 제외한다.
- 전체 원본 Movement를 통해 선택 밖 중간 운항, 동시각·연속 동방향 후보, 상충 기록, RAMP 미확정 중간 운항 가능성을 검사한다. 불명확하면 개별 작업을 유지한다. 후보 양쪽은 모두 선택 범위에 있어야 하며, 순서용 선택 밖 자료는 운항편수·정규화 진단에 포함하지 않는다.
- 추정 날짜 RAMP는 허용하되 상세에 추정을 표시한다. 예정시각 대체편은 연결하지 않는다. 명시 실제 날짜는 날짜 추정 규칙으로 덮어쓰지 않는다.
- 통합 시작=min(두 시작), 종료=max(두 종료), 재투입=통합 종료+출발편 이동이다. 대기도 연속 점유하며 도착편 이동은 별도 가산하지 않는다. 개별 작업은 기존 이동시간을 유지한다.
- 운항편 식별·중복/결항·충돌 처리는 유지하고 조업 작업만 분리한다. 연결은 실제 동일 조 배정의 증명이 아니라 사용자 운영 가정이다.

이는 표본에서 확인한 범위에 기반한 운영 규칙이다. 모든 공항·과거·미래 날짜에 대한 공식 서버 보장 문서를 확보한 것은 아니다.
`config/ubikais_contract.json`의 설정을 변경할 때는 근거·추가 표본·회귀 테스트를 함께 갱신한다.

## 2026-10-29 전체 조회 후 항공사 선별 검증

인천·김포·제주·김해·청주·대구의 2026-10-26/28 출발·도착 24개 조합과 인천 추가 대조를 실제 API로 확인했다. 전체 요청 140회, 항공사별 비교 112건에서 식별자·원본 레코드 내용·계획/실제 기준 정규화와 진단이 모두 일치했다. 선택 응답행 합계는 755건이며 고유 운항편수나 기간 편수로 합산하는 값은 아니다. LKE/RLH는 표본에서 개별·전체 선별 모두 0건이어서 실제 편이 있는 경우는 미확인이다. 전체 응답의 비표준 편명은 임의로 제외하지 않고 개별 조회로 대체한다.

쉼표 연결 srchAl이나 동일 파라미터 반복은 인천 표본에서 복수 항공사 합집합을 반환하지 않았다. 현재 선별 방식은 표본에서 관측한 편명 접두어 규칙이며 검증된 실제 운항사 필드가 아니다. `airline_prefix_verified` 등 기존 계약 플래그는 변경하지 않았다. 원본 레코드는 변경하지 않으며 정규화용 Batch.airline/Flight.query_airlines에는 전체 응답에서 선별한 코드 또는 개별 조회 코드를 보존한다.

위 비교는 수정 전의 소량 읽기 전용 조사이며, 수정 코드의 실제 API 검증과 자동 fixture 검증은 `docs/verification.md`에 별도로 기록한다.
