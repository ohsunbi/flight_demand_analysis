# 합의된 설계와 구현 범위

## 사용자 합의

- 과거 분석과 향후 계획 모두 사용. Cloud 공개 URL, 로그인 없음.
- 여러 공항 중 하나를 조회. 전체 항공사와 특정 복수 항공사 필수.
- 최대 31개 운영일. 기본 이번 달·RKSI·전체·예정·00:00·60분.
- 실제 주기장 우선, 없으면 예정. 편수도 선택된 시각에 귀속한다.
- 한국시간 사용을 사용자 확인. 날짜 없는 주기장 HHMM은 예정일 전후 가장 가까운 날짜를 사용하고 추정 건수를 표시한다.
- 공통 조업 오프셋: 출발 -50/+10/+20, 도착 -20/+30/+40분.
- 결항 제외, 출도착 독립 작업, 한 작업당 1개 조, 조 공동 투입 가능.
- 셀 최대 동시 수요, 기간 공통 자동 색상, 오른쪽 상세 패널.
- URL로 설정 복원, 자동 조회 없음, 결과의 영구 저장 없음.
- PNG 전체 기간·24시간, A4 가로 PDF. 30분 모드는 앞·뒤 12시간 열 분할.

## 계산

운영일 d = [d의 시작, 다음날 시작), 점유 = [기준시각+시작 오프셋, 기준시각+재투입 오프셋).
동시 종료·시작은 방향별 순변동을 묶어 적용한다. 양의 길이 구간만 집계한다.
전체 최대는 동일 순간의 출발+도착의 최대이며 방향별 독립 최대의 합이 아니다.
동률이면 가장 이른 시각, 이월 피크는 셀 시작이 대표시각이다. 0 수요 피크는 없음이다.
편수는 셀에 기준시각이 속한 편이다. 점유 겹침 편수와 다르다.
운영일 최대의 평균은 무운항일을 포함한다. 수집 실패를 0으로 바꾸지 않는다.
연속 구간 적분으로 H[k], G[k], 일별 조·분을 계산한다.

## 수집과 상태

분석 구간 [A,B), 방향별 오프셋 a/r에 대해 (A-r,B-a)와 [A,B)를 덮는 날짜를 조회하고 실제 datetime으로 필터한다.
관측한 원본 조회일 차이(예정일-조회일 0~1일)를 반영해 이전 조회일을 추가한다.
실제 우선은 날짜 추정의 이동을 포함해 앞뒤 1일을 추가한다. 응답이 원본 날짜 차이 범위를 벗어나면 실패 처리한다.
날짜·방향별 srchAl 빈 조건으로 전체 원본을 완결 수집·캐시한 뒤 fpId의 ICAO 3자리 접두어로 선택 항공사를 선별한다. 편명이 영문 3자리+숫자+선택 영문 접미사 형식이 아니면 해당 날짜·방향의 선택 항공사를 srchAl별로 개별 조회하고 그룹 전체를 대체한다. 부분 선별과 개별 응답을 섞지 않으며 네트워크 실패·불완전 수집·조회 날짜 규칙 이탈은 실패로 전파한다. 전체·개별 수집을 합쳐 최대 1,000개 조회 단위 제한을 적용하고 추가 대조가 한도를 넘으면 차단한다. 이는 HTTP 페이지·재시도 횟수 제한과 별도다.
전역 0.35초 간격·한 번에 한 네트워크 요청, 15초 timeout, 최대 2회 재시도, 최대 200페이지.
완료된 날짜 단위만 원자적으로 캐시한다. 오늘/내일 30분, 모레 이후 24시간, 과거 다음날 06시 이후 수집분 7일.
UI별 Job에 진행 상태와 중단 Event를 둔다. 실패/중단 시 이전 분석을 유지한다.
조회 입력·적용 결과·다운로드 식별자를 구분한다. 새 결과가 준비되면 함께 교체한다.

## 기술 결정

- Python 3.12, Streamlit 1.58.0 및 기존 고정 주요 패키지 조합. 기존 uv.lock을 바탕으로 신규 메타데이터·tzdata·개발 도구만 반영.
- 표준 라이브러리 urllib 수집. 원본의 endpoint·파라미터·캐시 TTL 정책을 참고해 안전 처리 재작성.
- Streamlit 내장 components v2로 표의 실제 클릭 값을 Python에 전달. 추가 프런트엔드 빌드 도구 없음.
- 엔진은 UI/보고서에 의존하지 않음. 보고서는 하나의 Analysis를 공유하며 결과 ID로 관리.
- Matplotlib Agg·객체 Figure·RLock·finally 정리. 글꼴 Nanum Gothic과 OFL 라이선스 동봉.
- 이미지는 최대 2천만 픽셀 안전 검사. 31일/48열 정상 범위는 단일 PNG에 포함됨.
- 영구 DB 없음. 원본 캐시는 신규 프로젝트 cache에만 저장, 검증 산출물은 artifacts에만 저장.
